# T-102 書籤擷取流程提速（只改 lexus_kit/collector/）

分支：feat/collector-flow。不要執行任何 git 指令。不得加入任何規避反爬的做法（不自動換 UA、不繞 Cloudflare/登入、不背景批次請求）。每次只處理使用者「當下這一頁」，且必須由使用者按書籤觸發；頁面載入速度與人工瀏覽相同。

## 目標
目前每篇要：開連結 → 按書籤 → 捲到底 → 關分頁。改成「每篇只需按一次書籤」：

1. **佇列放在瀏覽器**：列表／搜尋頁按書籤時，除了下載 queue json，也把連結存進該網站 origin 的 `localStorage`（key `lexus_queue`，格式 `[{url,title}]`，去重並保留已完成標記 `lexus_done`：url 或 thread/id 的陣列）。
2. **自動捲動**：Mobile01 文章頁也先捲到底（與 Dcard 同樣方式，確保懶載入完成）再擷取；Dcard 維持現有行為。
3. **存完自動下一步**：
   - Mobile01 多頁串：存完這頁，若有下一頁，toast 顯示「2 秒後前往下一頁（再按一次書籤）」並導向 `&p=N+1`；最後一頁則導向佇列中下一個未完成的串。
   - Dcard／Mobile01 最後一頁：標記 done，導向佇列下一個未完成的連結。佇列空了則 toast「佇列已完成」。
   - toast 加「停止自動跳轉」鈕（點了就留在原頁）。
   - 使用者到新頁後仍須自己按書籤（不要在頁面載入時自動執行擷取）。
4. **進度**：toast 顯示「已完成 X／佇列 Y」。
5. 重新產生 `bookmarklet.txt`（與現有同格式：`javascript:` + URL 編碼）。若 repo 內沒有產生腳本，新增 `collector/build_bookmarklet.py` 由 capture.js 產生，並壓縮不破壞語法。
6. 更新 `collector/README.md`：安裝書籤要貼到「新增網頁」的網址欄（不是網址列）；新流程 3 行說明；移除過時的「圖表註腳寫死 PTT」注意事項（analyze.py 已改）。

## 驗收
- `node --check collector/capture.js` 通過（若無 node，改用 `python` 檢查 bookmarklet.txt 可 URL decode 且括號平衡）。
- `bookmarklet.txt` decode 後與 capture.js 內容一致（除壓縮）。
- 寫一個 `collector/test_capture.html`（離線本地頁，模擬列表→文章流程用的假 DOM，不連任何網站）不需要；改在結果檔說明你如何驗證邏輯，並列出未能實測的部分（需要真實網站）。
