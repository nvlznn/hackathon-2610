分支：feat/multi-source。不要執行任何 git 指令。不要呼叫 Gemini API（Claude 會自己跑真正的標註）。
只改 `lexus_kit/label_with_gemini.py` 與 `lexus_kit/check_label_quality.py`。

## 背景
- 第一段標註（v1）：`data/labels.jsonl`，模型 gemini-3.5-flash-lite，1640 篇。
- 人工標註：`data/review_sheet.csv`（60 篇，`human_relevant/human_sentiment/human_stance`，讀法沿用 `score`）。
- 人工裁決：`data/disagreements.csv` 的 `adjudicated_*`（只有部分列、部分欄有填）。
- 第二段（v2）會用較強模型 + few-shot 範例重標部分文章，輸出 `data/labels_v2.jsonl`，需要工具判斷 v2 是否比 v1 好。

鐵則：不得把 AI 的值寫進任何 `human_*` / `adjudicated_*` 欄位；不得修改 `review_sheet.csv`、`disagreements.csv`、`labels.jsonl`。

## 1. `label_with_gemini.py`
新增參數（都是選用；不給時行為與現在相同，只多出下面第 4 點的新欄位）：
1. `--model <名稱>`：覆蓋 `GEMINI_MODEL` / 預設模型。
2. `--fewshot <檔案>`：讀入檔案全文，插在 PROMPT 規則之後、「標題：」之前，前面加一行 `以下是人工確認過答案的範例，請依同樣標準判斷：`。不給時 prompt 與現在逐字相同。
3. `--ids <檔案>`：每行一個 id（忽略空行與 `#` 開頭行），只標這些 id；仍然跳過 `--out` 中已標過的 id（可續跑）。檔案中找不到的 id 印出警告與數量。
4. `Label` schema 最後新增兩個欄位（不得改動、重排既有欄位與其 description）：
   - `confidence`：Enum 高／中／低。description：「對 relevant、sentiment、stance_to_dealer 三項判斷的把握。文意模糊、資訊不足、或規則難以套用時填低」
   - `reason`：str。description：「relevant、sentiment、stance_to_dealer 的判斷依據，60 字以內」
5. 每列輸出另加 `label_model`（實際使用的模型名）與 `fewshot`（few-shot 檔名，沒有則 null）。
6. `write_csv` 不需改（新欄位自然會進 CSV）。檔頭 docstring 補上新用法範例。

## 2. `check_label_quality.py` 新增子指令 `compare`
```
python check_label_quality.py compare --sheet data/review_sheet.csv --disagree data/disagreements.csv \
    --a data/labels.jsonl --b data/labels_v2.jsonl [--exclude data/fewshot_ids.txt] [--md <路徑>]
```
- 正確答案（gold）：每篇每欄，若 `disagreements.csv` 該欄 `adjudicated_*` 有填就用它，否則用 `review_sheet.csv` 的 `human_*`；兩者都空就不計。印出「裁決與人工不同」的格數（目前應為 2）。
- 比較範圍：review_sheet 的 id ∩ a 的 id ∩ b 的 id，扣掉 `--exclude` 檔中的 id（few-shot 範例，避免作弊）。印出範圍篇數與被排除數。
- 三欄（是否相關、情緒、對原廠立場）分別算 A vs gold、B vs gold 的一致率，格式 `85%（n=57）`，並算差值（百分點）。relevant 轉 是／否 比對，同 `score`。
- 列出 A、B 答案不同的每一格：id、title、欄位、A、B、gold、B 的 `confidence` 與 `reason`（若有）。
- 另外統計 b 檔全部篇數中 confidence 高／中／低的分布，以及 b 中 relevant 由 v1 的 是 變成 否 的篇數（用 a 對照，全部 b 的 id，不限 60 篇）。
- `--md <路徑>`：把以上寫成 Markdown（標題「v1 / v2 標註比較」、日期、資料說明含兩個檔的 `label_model`、一致率表、差異明細表、confidence 分布）。不要寫進 `out/label_quality.md`（那個檔有手寫段落）。
- 檔頭 docstring 補上 `compare` 用法。
