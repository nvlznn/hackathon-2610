# T-106 多來源後的趨勢圖與來源比較

分支：feat/multi-source。不要執行任何 git 指令。不要呼叫任何 API。只改 `lexus_kit/analyze.py`。

## 背景
加入 Mobile01（29 篇）、Dcard（22 篇）後重跑 `analyze.py`，出現兩個問題：
1. Mobile01 有 2007 年的舊討論串，`chart_4_quarterly.png` 的 X 軸被拉到 2007–2026，七十多個季度標籤疊在一起無法閱讀；而且 PTT 只有 2021 年起的連續爬取，把人工挑選的舊串放進趨勢會造成假的「2021 年暴增」。
2. Mobile01、Dcard 是人工挑選的討論串，流失傾向比例遠高於 PTT。summary 只列合併數字，讀者看不出各來源的差異。

## 要做的事
1. 每月趨勢（`06_monthly.csv` 與 `chart_4_quarterly.png`）只用 `source == "PTT"` 的文章（相關篇數、負面篇數、經銷商信任篇數都一樣）。
   - 圖的註腳改成：`趨勢僅用 PTT（連續爬取）n=<篇數>；Mobile01、Dcard 為人工挑選的討論串，不納入趨勢`。
   - X 軸標籤要清楚可讀：例如只在每年第 1 季標「2021」這種年份，或每隔幾季標一次；不得重疊。
2. summary.md「資料總覽」：
   - `資料期間` 改為每個來源各自列出，例如 `- 資料期間：PTT 2021-01-02 至 2026-10-01；Mobile01 …；Dcard …`。
3. summary.md 在「資料總覽」之後新增一節 `## 各來源比較`：每個來源一行，列出標註篇數、relevant 篇數、車主發文篇數、車主中猶豫或已轉外廠的比例（格式 `xx.x%（k/n）`，與現有寫法一致）。
   - 車主篇數 < 5 的來源，比例後面加「（樣本不足，不下結論）」。
   - 該節最後加一行：`- 註：Mobile01、Dcard 為人工挑選的討論串，比例不代表該平台整體；跨來源合併數字以 PTT 為主體。`
4. 其他所有輸出（01–05、07、08 的 CSV、其他圖、summary 其他段落）數字不得改變。

## 驗收（在 `lexus_kit/` 下執行，用 `.venv/bin/python`，輸出貼進結果檔）
```bash
cp -r out /tmp/t106_before
.venv/bin/python analyze.py
for f in 01_pain_by_location 02_churn_drivers 03_comment_voices 04_risk_by_age 05_risk_by_segment 07_quotes 08_persona_candidates; do cmp out/$f.csv /tmp/t106_before/$f.csv && echo "$f same"; done
diff /tmp/t106_before/summary.md out/summary.md
.venv/bin/python -c "import pandas as pd; m=pd.read_csv('out/06_monthly.csv', encoding='utf-8-sig'); print(m.iloc[:,0].min(), m.iloc[:,0].max(), m['相關篇數'].sum())"
```
- 06_monthly 的最早月份不得早於 2021-01，`相關篇數` 總和必須等於 PTT relevant 篇數（312）。
- diff 只能出現在「資料期間」與新增的「各來源比較」。
- 開啟 `out/chart_4_quarterly.png` 確認標籤沒有重疊（在結果檔描述你看到的 X 軸標籤）。
- 驗完刪除 `/tmp/t106_before`。
